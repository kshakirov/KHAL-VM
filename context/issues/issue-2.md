## Архитектурное уточнение к Issue #2 — `TypeTag + union Payload`

После обсуждения уточняем первый эксперимент с tagged values.

### Решение

Для первоначальной реализации машинное значение KHAL представляем явно:

```cpp
enum class TypeTag {
    INT,
    BOOL,
    NIL
    // остальные теги добавляются по мере необходимости
};

union Payload {
    int64_t integer;
    bool boolean;
};

struct Value {
    TypeTag tag;
    Payload payload;
};
```

`TypeTag` является **единственным дискриминантом значения**.

Не используем `std::variant`, поскольку он содержит собственную информацию об активной альтернативе. В таком случае получились бы два независимых механизма типизации:

```text
KHAL TypeTag
+
std::variant discriminator
```

Для текущего эксперимента это нежелательно: проверяем именно механизм tagged values самой KHAL.

### Инвариант

Смысл `Payload` определяется `TypeTag`:

```text
INT  → payload.integer
BOOL → payload.boolean
NIL  → значимый payload отсутствует
```

Следовательно, операция машины должна сначала проверить tag и только затем обращаться к соответствующему полю `union`.

Будущая операция типа:

```text
ADD_INT r1, r2 → r3
```

семантически выполняет:

```text
r1.tag == INT
r2.tag == INT
        ↓
прочитать integer payload
        ↓
сложить
        ↓
r3 = { INT, result }
```

Таким образом, допустимость операции определяется состоянием самой KHAL, а не типовой системой C++.

### Граница решения

`union` **не объявляется окончательным физическим представлением KHAL**.

Это прозрачная реализация первого семантического эксперимента:

```text
Value = Tag + Payload
```

Размер tag, размер payload, packing, alignment, NaN-boxing, pointer tagging и отображение на реальные аппаратные регистры относятся к будущему этапу lowering и сейчас не фиксируются.

### Ближайшая цель Issue #2

1. Ввести `TypeTag`.
2. Ввести `Payload`.
3. Ввести `Value = TypeTag + Payload`.
4. Создать register file из 256 значений.
5. Проверить запись и чтение как минимум `INT`, `BOOL` и `NIL`.
6. Не вводить арифметику и формат bytecode до проверки этого базового машинного состояния.
