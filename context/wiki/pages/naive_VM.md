# Наивное представление KHAL-VM

Наивная модель KHAL-VM — это калькулятор с памятью, который читает текст выражения слева направо в один проход, сразу превращает его в числовые команды и мгновенно выполняет их, используя 256 пронумерованных ячеек для хранения промежуточных результатов.

## Анатомия наивной модели «на пальцах»:

1. **Калькулятор с памятью:** Машина не плодит сложные объекты и ООП-иерархии. Её единственная задача — взять данные, применить к ним базовую математику (целые числа, фиксированная точка, рациональные дроби) и выдать результат.
2. **Один проход (Принцип Вирта):** Компилятор не строит тяжелых деревьев (AST) в памяти и не заглядывает вперед. Он читает текст посимвольно слева направо. Как только он видит законченное выражение — он тут же генерирует числовую команду для нашего калькулятора.
3. **Пронумерованные полки (Регистры):** Машина не знает имен переменных `a`, `b` или `c`. Внутри виртуального кремния существуют только номера полок от 0 до 255. Всё вычисление — это перекладывание данных между этими пронумерованными ячейками.


# KHAL-VM: Природа и реализация Instruction Pointer (IP)

## 1. Концептуальная сущность
**Instruction Pointer ($IP$)** в KHAL-VM не является предскомпилированной программой или объектом байт-кода. 

* **Байт-код (`std::vector<uint32_t>`)** — это пассивный, неизменяемый результат работы функции `compile()`. Он представляет собой плоский массив чисел в памяти.
* **$IP$** — это **динамический курсор состояния рантайма**, который рождается исключительно в момент запуска метода `execute()` внутри виртуальной машины.

## 2. Физическое выражение в C++
На уровне C++20 $IP$ материализуется как локальная переменная-индекс (`size_t`), определяющая смещение относительно начала массива байт-кода:

```cpp
void execute(const std::vector<uint32_t>& bytecode) {
    size_t ip = 0; // IP инициализирован на начало потока инструкций
    
    // Элементарный такт:
    uint32_t opcode = bytecode[ip]; // 1. Fetch (Выборка по IP)
    ip++;                            // 2. Advance (Продвижение)
}
```






# KHAL-VM: Анатомия регистра и тип-паннинг (Tagged Union)

## 1. Концептуальная природа регистра
В регистровой архитектуре KHAL-VM регистровый файл состоит из 256 фиксированных слотов. Каждый слот представляет собой **Tagged Union** (дискриминированное объединение / Sum Type $A \sqcup B \sqcup C$).

Структура регистра включает два базовых элемента:
1. **Тег типа (`TypeTag`)** — дискриминант (1 байт), определяющий семантику и тип данных, находящихся в слоте в данный момент.
2. **Полезная нагрузка (`Payload`)** — область физической памяти фиксированного размера (8 байт / 64 бита).

## 2. Физическое наложение памяти (Type-Punning)
Для исключения рантайм-оверхеда на сдвиги битов (`>>`), маскирование (`&`) и динамические аллокации, область `Payload` организуется через нативное наложение памяти (`union`).

Это позволяет интерпретировать одну и ту же 64-битную ячейку памяти RAM несколькими способами с нулевой стоимости доступа (Zero Runtime Cost):
* **Единое 64-битное целое:** прямая работа с 64-битным значением (`int64_t` / `uint64_t`).
* **Разбиение на 32-битные половинки:** прямое обращение к младшим (`low`) и старшим (`high`) 32 битам (`uint32_t`) без битовых операций. Это используется для типов данных с двойной структурой (например, числитель/знаменатель рациональной дроби или целая/дробная части фиксированной точки `32.32`).

## 3. Гарантия типа и контракт VM
* `TypeTag` гарантирует безопасную интерпретацию содержимого `union` на уровне логики виртуальной машины.
* При записи в регистр VM одновременно обновляет `TypeTag` и соответствующее поле `Payload`.
* При чтении VM проверяет `TypeTag` и извлекает данные из соответствующего представления `Payload` без дополнительных преобразований памяти.


# KHAL-VM: Диспетчеризация инструкций и строгая система типов

## 1. Механизм диспетчеризации (Switch-Dispatch)
Передача управления в `execute()` реализована через классический прозрачный цикл с конструкцией `switch(opcode)` по принципу Бритвы Оккама:

```cpp
void execute(const std::vector<uint32_t>& bytecode) {
    size_t ip = 0;
    
    while (ip < bytecode.size()) {
        uint32_t opcode = bytecode[ip];
        
        switch (opcode) {
            case OP_ADD: {
                uint32_t dst = bytecode[ip + 1];
                uint32_t src = bytecode[ip + 2];
                
                // Проверка Харперовского инварианта типов
                if (R[dst].tag != R[src].tag) {
                    this->state = VM_ERROR_TYPE_MISMATCH;
                    return;
                }
                
                // Выполнение чистой операции
                execute_add(R[dst], R[src]);
                ip += 3; // Advance
                break;
            }
            // ... остальные обработчики инструкций
        }
    }
}
```

# KHAL-VM: Разделение инструкций загрузки (LOAD) и выполнения (EXECUTE)

## 1. Фундаментальный принцип работы с операндами
В байт-коде KHAL-VM операнды имеют принципиально разную природу в зависимости от типа инструкции:

1. **Операнд-Индекс (Register Index):** Номер слота в массиве регистров (от 0 до 255). Служит адресом для чтения или записи данных.
2. **Операнд-Значение (Immediate Constant):** Сырое числовое значение, зашитое прямо в поток байт-кода.

Инструкции вычислительного характера (например, `OP_ADD`, `OP_SUB`) **никогда не читают сырые данные из байт-кода напрямую**. Они оперируют исключительно *индексами регистров*.

---

## 2. Роль явных инструкций загрузки (`OP_LOAD_*`)
Поток байт-кода состоит из плоских 32-битных чисел. Виртуальная машина не может угадать семантику данных без явной команды. 

Занесение констант из байт-кода в регистры — это обязанность специальных предписывающих инструкций:
* `OP_LOAD_INT` — считывает 64-битное целое из байт-кода, выставляет тег `TAG_INT` и записывает значение в указанный регистр.
* `OP_LOAD_FIXED` / `OP_LOAD_RAT` — считывают соответствующие структуры данных, выставляют нужный `TypeTag` и заполняют `Payload`.

---

## 3. Полный жизненный цикл вычисления (Пример: 2 + 3 = 5)

Компилятор разворачивает выражение в цепочку атомарных тактов выполнения.

### Структура потока байт-кода:
```text
[ OP_LOAD_INT, R1, 2,  OP_LOAD_INT, R2, 3,  OP_ADD, R1, R2 ]
├────── Такт 1 ───────┼────── Такт 2 ───────┼─── Такт 3 ────┤
